# `corpus`

Manage and evaluate the placement corpus.

```
legolization corpus list | generate | download | verify | collect | assemble | evaluate
```

This is the regression harness. It sweeps a fixed set of test models through the
placement strategies, assembles a scorecard, and diffs it against a committed
baseline. Use it to answer "did my change make the project better or worse?" — not to
build anything.

The methodology — what the numbers mean, which regressions matter, and the rules
around the baseline — lives in the
[self-evaluation playbook](../../guides/self-evaluation-playbook.md). This page is the
command surface.

---

## Where things live

| Thing | Location |
| --- | --- |
| Corpus manifest (committed truth) | `src/legolization/data/corpus/manifest.toml` |
| Generated and downloaded inputs | Platform user-data storage (`$LEGOLIZATION_DATA_HOME` overrides) |
| Run artifacts | `./legolization-eval/runs/` (`--out` overrides) |
| Baselines, in a checkout | `eval/baselines/scorecard.json`, `scorecard-mesh.json` |
| Baselines, outside a checkout | `./legolization-eval/baselines/` |

Inputs are **not** vendored in the repository. Synthetic models are generated by
deterministic code; meshes are downloaded from pinned URLs and verified against
recorded SHA-256 hashes, because their licences do not permit redistribution.

## Two kinds

| Kind | Cost | Default |
| --- | --- | --- |
| `synthetic` | Seconds per model | The default for `collect` |
| `mesh` | Tens of minutes to hours per model | Opt-in |

`evaluate` defaults to **both** kinds; `collect` defaults to `synthetic` only. Naming
a mesh model without `--kind mesh` fails with a hint rather than silently running for
an hour.

## Preparing the corpus

```sh
legolization corpus list        # what exists and what is available locally
legolization corpus generate    # build synthetic inputs into user-data storage
legolization corpus download    # fetch pinned meshes (network, once)
legolization corpus verify      # check every input against its pinned hash
```

| Operation | Flags |
| --- | --- |
| `list` | `--json` |
| `generate` | `--models NAME,...`, `--traits TRAIT,...`, `--json` |
| `download` | `--models NAME,...`, `--json` |
| `verify` | `--json` |

`--models` restricts to named manifest entries; `--traits` restricts to models
carrying any of the given traits (`thin-shell`, `spanning`, and so on).

Exit 0 when nothing failed, exit 1 if any model failed.

## Sweeping

```sh
legolization corpus collect --kind synthetic
```

| Flag | Type | Default | Effect |
| --- | --- | --- | --- |
| `--models NAME,...` | list | all | Restrict to named models. |
| `--traits TRAIT,...` | list | all | Restrict by trait. |
| `--kind` | `mesh`, `synthetic` | **`synthetic`** | One kind per run. Mixed-kind sweeps do not exist. |
| `--strategies NAME,...` | list | all | Placement strategies to run. |
| `--jobs` | int | `0` | Parallel workers. `0` means one per candidate, CPU-capped. |
| `--seed` | int | `0` | Base seed. |
| `--seeds N,N,...` | list | none | Run every strategy once per seed. |
| `--out` | path | `./legolization-eval/runs` | Run output root. |
| `--timeout` | float | `300.0` | Per-candidate timeout in seconds. |
| `--fresh` | flag | off | Ignore exact successful artifacts and rerun. |
| `--json` | flag | off | |

`collect` writes one atomic artifact per model/strategy/seed plus a
`collection.json`, under a UTC-stamped directory. It **reuses** artifacts whose
commit, source, config, and input identity match exactly, and retries failures — so
an interrupted sweep resumes cheaply. Use `--fresh` only when an exact success should
deliberately be ignored.

Exit 0 when the collection is complete, exit 1 when it is not.

## Scoring

```sh
legolization corpus assemble
```

| Flag | Type | Default | Effect |
| --- | --- | --- | --- |
| `--runs PATH` | path | `./legolization-eval/runs` | Runs root to pick the newest collection from, or one `collection.json`. |
| `--out PATH` | path | `./legolization-eval/runs` | Scorecard output root. |
| `--baseline PATH` | path | canonical | Baseline to diff against. |
| `--write-baseline` | flag | off | **Replace the canonical baseline.** |
| `--tolerance` | float | `0.05` | Relative tolerance for objective regressions. |
| `--json` | flag | off | |

`assemble` validates that the expected model × strategy × seed matrix is complete,
then writes `scorecard.json` and `scorecard.md`. It runs no placement — it only reads
what `collect` produced.

Exit 0 when clean; exit 2 on a failed expectation or a HARD regression; exit 1 on an
operational error such as an incomplete collection.

!!! danger "`--write-baseline` is the one move that defeats the harness"

    It replaces the committed record of how good the project currently is. It
    requires the full-kind, every-strategy, seed-0 scope and a failure-free
    evaluation — but those checks cannot tell whether *you understood* the change.

    Never write a baseline to silence a regression you cannot explain. Refresh it
    only after reading the comparison and accepting every changed row, and commit the
    new baseline together with the code change that justified it.

## Both at once

```sh
legolization corpus evaluate
legolization corpus evaluate --kind synthetic
```

| Flag | Type | Default |
| --- | --- | --- |
| `--kind` | `mesh`, `synthetic` | **both** |
| `--strategies`, `--jobs`, `--seed`, `--seeds`, `--out`, `--json` | | as for `collect` |

`evaluate` collects and assembles in one operation. It **can never write a baseline**
— that is deliberately only available on `assemble`, where you have had the chance to
read the scorecard first.

---

## Reading the scorecard

| Metric | Meaning |
| --- | --- |
| `buildable_count` | How many strategies produced a buildable result for this model. Higher is better. |
| winner `objective_total` | Weighted cost/stability/aesthetics/colour sum. Lower is better. **Comparable only within one model**, never across models. |
| `expect_min_buildable` | The manifest's encoded expectation of *current reality*, not aspiration. Some shapes expect 0 by design. |
| `seed_spread` | Variance across seeds — quantify it with `--seeds 0,1,2`. |

A regression counts as **HARD** when the buildable-strategy count drops, an
expectation newly fails, or the winner objective worsens beyond `--tolerance`. Those
must be explained or fixed. Lines prefixed `note:` are context, not failures — an
unavailable mesh, for instance, is a note with exit 0.

Seconds are noise. Never compare timings across runs; use the
[performance testing guide](../../guides/performance-testing.md) for that.

---

## A typical loop

```sh
legolization corpus verify
legolization corpus collect --kind synthetic
legolization corpus assemble
# read the scorecard, find the worst row, fix it, repeat

# only after reading and accepting every change:
legolization corpus assemble --write-baseline
```

Meshes are never part of the inner loop. Run them separately, in the background, when
a change could plausibly affect them.
